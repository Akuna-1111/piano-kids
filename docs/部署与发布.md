# 部署与发布（GitHub + Cloudflare Pages）

> 这份是**操作手册**：从「本地仓库」到「公网 HTTPS 域名」的完整步骤与踩坑点。
> 发布链路上的每一步都要人来点（登录、授权），所以步骤写得很具体。

---

## 0. 这个应用怎么部署才合适

| 事实 | 对部署的影响 |
| --- | --- |
| 纯静态（Vite 构建出 `dist/`） | 任意静态托管都行，不需要服务器、不需要数据库 |
| 全部数据在 `localStorage` | 没有后端、没有环境变量、没有密钥 —— 构建时不需要任何 Secret |
| **路由是 hash 路由**（`#/settings`） | **不需要 SPA 回退规则**：任何深链都请求 `/index.html`，不存在 404 |
| PWA（`public/manifest.webmanifest` + `public/sw.js`） | 必须 HTTPS 才能安装；`pages.dev` 自带证书 |

## 1. GitHub

### 1.0 ⚠️ 本机网络环境：`github.com` 的 HTTPS 是不可用的

**实测结论（2026-09，本机）**：

| 目标 | 结果 |
| --- | --- |
| `api.github.com`（HTTPS） | **稳定可用**，200 / 0.35–0.97 s，连续多次都通 |
| `github.com`（HTTPS，含 git over HTTPS） | **不可用**：系统解析到 `20.205.243.166`，该地址 443 是黑洞（curl 5/5 超时、`git ls-remote` 3/3 失败、每个耗时 ~21 s） |
| 换成 `140.82.112.4` / `20.27.177.113` | 偶尔 200，但**几分钟内就被掐**（自适应封锁）；`POST /login/oauth/access_token` 三次全超时 |
| `ssh.github.com:443`（SSH） | **稳定可用**，`ssh -T` 返回 `Hi Akuna-1111! You've successfully authenticated`，`git ls-remote` 6 s 完成 |

**所以结论是：这台机器上不要走 `github.com` 的 HTTPS，走 SSH(443) 与 api。**

- ❌ **`gh auth login --web`（设备码）在这台机器上会失败**：设备码能拿到（那一步走运过去了），
  但换令牌的 `POST https://github.com/login/oauth/access_token` 会被掐断 ——
  报错是 `failed to authenticate via web browser: ... unexpected EOF` 或直接超时。
  **别在这上面反复试**，一次不够就换路
- ✅ 本机 `~/.ssh/id_ed25519` **已经注册在 GitHub 账号 `Akuna-1111` 上**，直接可用
- ✅ 需要调 API（建仓库、加密钥、读用户信息）时走 `api.github.com`，它一直很稳

### 1.1 用 SSH(443) 推送（本机推荐路径）

仓库建好之后（网页建也行，见 1.2），remote 用**显式 443 端口**，绕开被污染的 443 默认路径：

```powershell
git remote add origin ssh://git@ssh.github.com:443/Akuna-1111/piano-kids.git
git push -u origin main
```

> 为什么写 `ssh://git@ssh.github.com:443/...` 而不是 `git@github.com:...`：
> `github.com:22` 与 `github.com:443`（HTTPS）都受影响，而 `ssh.github.com:443`
> 是 GitHub 官方给「22 被挡」的网络准备的另一条入口，实测稳定。
> 想少打字可以在 `~/.ssh/config` 里写 `Host github.com / HostName ssh.github.com / Port 443`，
> 但那样是**机器级**配置，会影响其他项目 —— 这里选择只改本仓库的 remote。

验证（推之前就能确认通路）：

```powershell
git ls-remote ssh://git@ssh.github.com:443/Akuna-1111/piano-kids.git   # 仓库已建：列出引用；未建：Repository not found
```

### 1.2 建仓库

- 网页：打开 <https://github.com/new?name=piano-kids&visibility=public> →
  **不要勾** README / .gitignore / license（本地已有内容，勾了会冲突）→ Create repository
- 或者（需要令牌）`gh repo create piano-kids --public --source . --remote origin --push`

### 1.3 应急手段：本地通路代理（能用，但不要依赖）

`scripts/local-github-proxy.mjs` 是一个只做 TCP 隧道的 CONNECT 代理，
把 `github.com:443` 钉到候选 IP（`20.27.177.113` / `140.82.112.4` …），其余域名照常解析。
**不做 TLS 终止**，证书校验仍是 git/gh 直连 GitHub 完成的。

```powershell
node scripts/local-github-proxy.mjs 8787
$env:HTTPS_PROXY='http://127.0.0.1:8787'
git -c http.proxy=http://127.0.0.1:8787 ls-remote https://github.com/git/git HEAD
```

实测：**开通时确实能把 `git ls-remote` 从 21 s 失败变成 1.2 s 成功**，
但几分钟内就会被掐，`POST` 到 OAuth 端点仍然失败 —— 所以它只是应急，
**正式路径是 SSH(443)**。用完记得 `job_kill` / Ctrl-C。

### 1.4 日常推送

```powershell
git add -A
git commit -m "说明这次改了什么"
git push
```

> ⚠️ 本仓库没有第二个副本，**推送前先确认 `npm run test` 全绿**；
> 快照 zip（`E:\piano_D_snapshots`）仍是最后一道保险。

## 2. Cloudflare Pages（镜像 GitHub 仓库 + 免费域名）

### 2.1 在浏览器里操作（一次性）

```text
1. 打开 https://dash.cloudflare.com → 登录（没有账号就用邮箱注册，免费）
2. 左侧 Workers & Pages → Create → Pages → Connect to Git
3. 授权 GitHub（Install & Authorize Cloudflare Pages）→ 选中仓库 piano-kids
4. 构建配置：
     Framework preset      ：Vite
     Build command         ：npm run build
     Build output directory：dist
     Root directory        ：（留空）
   Environment variables   ：不需要（本项目构建期没有任何环境变量）
5. Save and Deploy
```

构建读 `.nvmrc`（值为 `20`），所以不用手动设 `NODE_VERSION`。

### 2.2 结果

- 每次 `git push` 到 `main` 会自动重新构建并发布（这就是「镜像」）
- 每个 PR 会额外得到一份预览地址
- 免费域名形如 `https://piano-kids.pages.dev`（在项目首页与 Deployments 里能看到）
- 想换成自己的域名：项目 → Custom domains → Set up a domain

### 2.3 上线后要验的几件事

| 项 | 怎么验 | 期望 |
| --- | --- | --- |
| 页面能开 | 打开 `https://<项目>.pages.dev` | 首页即自由弹，键盘可点响 |
| 真机布局 | iPad 上量白键宽度 | 与 `#/tuning` 读数一致；无横向溢出 |
| PWA 可安装 | Safari「添加到主屏幕」 | 有图标与名称，离线打开不白屏 |
| 路由 | 直接访问 `.../#/settings` | 正常进设置页（hash 路由，不需要回退规则） |
| 数据 | 弹几首、刷新 | 星星与进度还在（localStorage） |
| 缓存头 | DevTools → Network 看 `/assets/*.js` | `cache-control: public, max-age=31536000, immutable` |
| Service Worker | DevTools → Application → Service Workers | 状态 activated；`/sw.js` 响应 `no-cache` |

`public/_headers` 里的规则就是上表最后两条的来源（Pages 会读取 dist 里的 `_headers`）。

### 2.4 上线自检脚本

上面那张表里「PWA 与键盘」两项可以在本机用**生产构建**先验一遍 ——
Service Worker 只在生产构建里注册（`import.meta.env.PROD`），开发环境永远不注册，
所以「开发环境正常」不能说明线上正常：

```bash
npm run build
npx vite preview --host 127.0.0.1 --port 5173 --strictPort     # 另开一个终端
npm run shot -- "#/" --script scripts/flows/pwa-check.js
```

> ⚠️ preview 一定要带 `--host 127.0.0.1`：默认只绑 `localhost`（IPv6），
> 而探针访问 `127.0.0.1`，会得到 `ERR_CONNECTION_REFUSED`、看起来像「线上白屏」，
> 其实是探针连不上自己刚起的服务器（踩过一次）。

实测读数（2026-09，iPad 竖屏视口）：

```json
{"mounted":true,
 "manifest":{"href":"./manifest.webmanifest","ok":true},
 "serviceWorker":{"supported":true,"count":1,"scopes":[".../"],"controller":true},
 "caches":["piano-kids-v3-0-0"],
 "keyboard":{"whites":15,"blacks":10,"keyWidth":122.1,"keyHeight":780,"scrollable":1054},
 "overflowX":0}
```

`keyWidth: 122.1` 就是真实 23.5mm 反推出来的键宽；`scrollable: 1054` 说明键盘宽出屏幕、
可以左右拖动 —— 这两条都符合 `AGENTS.md` §7 的约定。

### 2.5 构建环境已在本机预演（等价于 Cloudflare 的构建）

「本地能构建、线上构建失败」这类问题可以在推送前排除掉：**干净检出**（只有 git 跟踪的文件，
没有 `node_modules`、没有本机残留）后跑一遍 Pages 会跑的两条命令：

```powershell
git clone --no-hardlinks . E:\piano_D_cibuild     # 等价于 Cloudflare 的 checkout
cd E:\piano_D_cibuild
npm ci --no-audit --no-fund                        # 与 Pages 相同：按 lockfile 装
npm run build                                      # Pages 的构建命令
```

**实测（2026-09）**：171 个文件、`npm ci` 装 191 个包、`npm run build` **622 ms 成功且无任何 WARNING**，
`dist/` 里有 `index.html` / `assets/` / `manifest.webmanifest` / `sw.js` / `_headers`。

> 关键点：**`public/_headers` 必须在 dist 里**（Pages 读的是构建产物里的这份）。
> 预演完把 `E:\piano_D_cibuild` 删掉，别让它被误当成第二份源码。

### 2.6 备用通道：`wrangler` 直传（不需要 Git 集成）

如果第 2.1 步的 GitHub 授权跳转不顺利，可以先直传拿到域名（**Git 集成仍需 2.1 的授权**，
两者互不冲突：同名项目后补授权会保留域名）：

```powershell
# 1) 先在浏览器里建一个 API Token：My Profile → API Tokens → Create Token
#    → 模板选「Edit Cloudflare Workers」（含 Pages 权限）；记下 Token 与 Account ID
$env:CLOUDFLARE_API_TOKEN='<令牌>'
$env:CLOUDFLARE_ACCOUNT_ID='<Account ID>'

npm run build
npx wrangler pages project create piano-kids --production-branch main
npx wrangler pages deploy dist --project-name piano-kids
```

本机已确认：`npx wrangler --version` → **4.134.0**；`api.cloudflare.com` 可达（未带令牌时 403，属正常）。

**直传的代价**：不会随 `git push` 自动重建 —— 每次改完要重新 `npm run build && npx wrangler pages deploy`。
所以它只是「先上线」的应急路径，长期仍建议补上 2.1 的 Git 集成。

## 3. 为什么没有加 CSP

`public/_headers` 里**故意不写 `Content-Security-Policy`**：

- 键盘的键宽/键高是运行时算出来写在**内联 style** 上的（真实 23.5mm 反推）
- 谱面用 SVG，皮肤用 `--skin-*` 变量，导出的图标是 data URI
- 一条没在本机逐页验过的 CSP（尤其是 `style-src`）会直接把琴键尺寸或皮肤弄坏，
  而这类故障在部署环境里最难查

要加 CSP 的话，先在本地验证：

```bash
npm run build
npx vite preview --port 4173      # 本机起一个与线上同构的静态服务
# 然后逐个路由走一遍：首页弹奏 / 跟弹 / 两个小挑战 / 节拍挑战 / 装扮 / 设置 / 自检 / 导入
```

## 4. 上线前的固定流程

```bash
npm run typecheck     # 0 error
npm run test          # 561 用例（含排版层级 / CSS 语法 / 设计规范 / 文档完整性守卫）

```

构建输出里出现任何 `▲ [WARNING]` 都要先解决再推 —— 那条警告曾经对应
一个「样式被静默截断」的真实缺陷（见 `docs/开发进度与验收.md`）。
