## 1. 这是什么

**儿童钢琴启蒙网页应用（V3.0）** —— 离线优先的 PWA，给 5–8 岁孩子第一次接触钢琴用。
一台 **iPad 第 7 代（10.2"）** 是主要真机。**没有后端、没有账号、没有付费 / 广告 / 抽卡 / 排行。**
核心动作只有三个：**看见琴键 → 按下 → 听见声音**。

## 6. 已定决策（不要重开，除非用户提出）

| 决策 | 结论 |
| --- | --- |
| 触控力度 | 不做（iPad 上无法可靠取到） |
| PDF 识谱 / OMR | 不做 |
| 按住时长判分 | 不做（只做「可见的按住提示」）；真机数据没回来之前不再推进 |
| 初学音符时值 | 全音符（**无符干无符尾**）；音符难度轴只有音域 |
| 音色 ↔ 皮肤 | 不做联动 |
| 完成页 | 只保留 8 个元素（标题 / 星 / 一行事实 / 成长值 / 皮肤样品 / 获得提示 / 三个按钮 / 退出） |
| 数字简谱 / 唱名拼音 |
| 首页形态 | **首页就是自由弹**（整块键盘）+ 顶栏「跟我弹 · 小钢琴 · 小挑战」与右侧 HUD；`/free` 已删除 |
| 首页形态（旧记录） | **三个一级入口**（跟我弹 / 自由弹 / 小挑战）+ 顶栏里放装扮与星星；**首页刻意不放琴键**（偏离设计规范 Appendix D 1–2，见进度文档《首页的形态》） |
| 键盘档位 | **只提供 15 键**（C3–C5）＝ 15 白键 + 10 黑键；**键宽保持真实 23.5mm**（允许宽出屏幕、可横向拖动），**默认视窗以中央C 为中心** | 默认开启，开关在设置页 |
| 教材曲目怎么进库 | **只能由用户导入**（应用不含教材内容）：`core/content/` 的内容包机制；拼音/简谱粘贴 → 校验 → 存本机 |
| AI 读谱（照片 → 简谱） | **不做**：给孩子的曲谱错一个音就是教错音；旋律只能由人给，或来自 MusicXML / MIDI |
| 节拍挑战 | V1 判定窗 ±90/±180ms、预备 4 拍、正式 16 拍、速度 60/80/100；**多按不扣分**；不给成长值 |
| 滑动琴键 | 按**滑奏**处理（限速 65ms/音、力度上限 0.6、被挡下的音补发）；**不要再从电平找这类问题** |

## 7. Token 预算与工作方式（开发流程的一部分）

**成本公式**：一轮的上下文 = 上一轮的全部内容 + 新内容。于是有三条乘法关系：

- 我写出去的每个字，**在之后的每一轮都要再付一次费** → 长回复是复利支出；
- 拆成多次单步编辑，**每次都要重发整个上下文** → 轮数是乘法因子；
- 大文件读进上下文后，**每一轮都要重发** → 读得多 = 一直付。

五份文档合计 108 KB（≈ 7 万 token），完整读一遍的代价大于实现一个中等特性。所以：

| # | 规则 | 替换掉的旧做法 |
| --- | --- | --- |
| 1 | 开场只读 `AGENTS.md`（自动注入）+ 本文件 | 通读三份大文档 |
| 2 | 大文档按需检索：`grep` 定位 → `read` 带 `offset/limit`（≤120 行） | 全文通读 2758 行规范 |
| 3 | 视觉改动**按节读规范并声明命中的节号**；禁止项 / 对比度 / Token 交给自动化守卫 | 「凭印象认为符合」与「全量通读」之间取中间态 |
| 4 | 同一文件的改动**一笔完成**；互相独立的工具调用放进**同一条消息** | 一次改名拆成两笔（顺带踩了两次 Vite 缓存陷阱） |
| 5 | 探针 / 测试的原始输出**写文件**，只回 ≤5 行结论 | 把 `.shots` 的明细表打印进对话 |
| 6 | 迭代中只跑**相关的那一个测试文件**；任务收尾跑一次全量 | 每改一处就跑 481 个用例 |
| 7 | 回复 ≤ 一段 + 一张小表；**细节写进 `docs/开发进度与验收.md`，不写进对话** | 每轮 1500–2500 字的总结（且被永久重发） |
| 8 | 不复述需求、不复述规范、不重开 §6 的已定决策 | 把上下文里已有的东西再讲一遍 |

**每轮收尾自检**：*这一轮的内容，如果之后 30 轮都要重复付费，我会怎么写？*

**反例账本**（真实发生过的浪费，用来判断规则有没有生效）：

| 事故 | 违反的规则 |
| --- | --- |
| `docs/开发进度与验收.md` 被 PowerShell 写坏 1381 字符，恢复花了整轮诊断 + 三个脚本 | AGENTS §11 + 规则 4 |
| `ReferenceError: X is not defined` 判了两次，都是改名 / 加引用拆成两笔编辑 | 规则 4 |
| 同一份进度文档在一个会话里被通读 5 遍 | 规则 1、2 |
| 连续多轮以 2000 字总结收尾 | 规则 7 |

---

### 两条漏掉、但影响最大的

- **一项工作开一个新会话**：上下文每轮都要重发，长会话本身就是二次成本。
  换任务前把结论写进文档，然后开新会话，而不是在同一段对话里接着做。
- **大范围探查交给 subagent**：它有自己的上下文窗口，读完只回一段结论 ——
  那几万 token 不会进入本会话。凡是「把三份大文档读一遍再回答」的活都该这样派出去。
